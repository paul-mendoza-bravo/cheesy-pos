00 Visión general

Microservicio FastAPI que automatiza el módulo "Tomar Orden" del POS Cheesy. Convierte mensajes informales de WhatsApp en órdenes estructuradas, validadas, costeadas, y persistidas en Supabase. La inserción detona Realtime hacia el frontend en Vercel, que actualiza la cocina al instante.

Entrada

WhatsApp Cloud API

Mensajes de cliente recibidos vía webhook de Meta. Texto libre.

Cerebro

LLM (Claude / OpenAI)

System prompt estricto fuerza salida JSON con la forma OrdenExtraida.

Verdad

Catálogo canónico

menu_definitions.py recalcula precios y COGS — el LLM nunca decide montos.

Persistencia

Supabase Postgres

Inyección transaccional: orders → order_items → order_events.

Salida

Realtime → Vercel

El frontend escucha INSERTs y muestra la orden en cocina + alerta sonora.

Salida

WhatsApp respuesta

BackgroundTask envía respuesta_bot al cliente sin bloquear el HTTP.

02 Componentes del sistema

Cada módulo tiene una única responsabilidad. El backend nunca confía en montos del LLM.

routes/webhook.py

Orquestador del pipeline

Recibe el mensaje, llama al LLM, valida, recostea, persiste y dispara la respuesta.

core/session_manager.py

Contexto conversacional

Almacén in-memory de mensajes por número, TTL 30 min. Permite responder "sí, porfa" cuando el bot ofreció una bebida.

core/llm_processor.py

Extracción IA

System prompt con menú embebido. Output: OrdenExtraida (Pydantic). Hoy mockeado — sustituir por SDK real.

core/menu_definitions.py

Fuente de verdad

Catálogo con precio_venta y cogs. Modificador "doble" suma +$30 venta / +$18 COGS.

core/order_calculator.py

Recosteo + validación

Recalcula total_order, total_cogs, ganancia bruta y % margen. Rechaza productos fuera del menú.

core/financials.py

Métricas del turno

Free Cash Flow, punto de equilibrio (~13 hamburguesas), faltante para cubrir $350 MXN de nómina diaria.

core/database.py

Inyección Supabase

3 INSERT secuenciales (orders → items → events). Genera UUID corto como order_id.

core/whatsapp_client.py

Envío async

Cliente httpx que llama a Meta Graph API. Disparado como BackgroundTask.

routes/dashboard.py

Dashboard SUPERADMIN

Endpoints /dashboard/* para resumen financiero y status de equilibrio.

03 Pipeline de procesamiento

Secuencia exacta que ejecuta POST /webhook/cheesy-pos ante cada mensaje.

Recepción del webhook

Meta entrega el payload. FastAPI valida contra IncomingMessage (campos mensaje_cliente y numero_telefono). 400 automático si el schema no encaja.

Recuperación de sesión

obtener_o_crear_sesion(numero) devuelve el historial de chat (TTL 30 min, in-memory). Se agrega el mensaje entrante con rol user.

Inferencia LLM

Se envía el system prompt (menú estricto + reglas) + historial al modelo. Devuelve JSON: estado_pedido, respuesta_bot, items[], direccion. Validado por Pydantic.

Validación de catálogo

validar_orden(items) recorre cada item y verifica que el producto exista en MENU y cantidad > 0. Si falla, fuerza EN_PROCESO y reescribe la respuesta.

Recosteo determinista

calcular_metricas_financieras_orden() calcula total_order, total_cogs, ganancia_bruta y % margen usando exclusivamente el catálogo canónico. Los precios sugeridos por el LLM se descartan.

Persistencia transaccional

Solo si estado_pedido == "COMPLETO": inyectar_orden_en_supabase() genera UUID corto e inserta en orders (status PENDING) → order_items (con modifiers JSON) → order_events. El INSERT en orders detona Supabase Realtime.

Respuesta async al cliente

Un BackgroundTask dispara enviar_mensaje_whatsapp(numero, respuesta_bot). La API responde HTTP 200 sin esperar a Meta.

Limpieza

Si la orden quedó COMPLETO, sesion.limpiar() vacía el historial para que el próximo mensaje del mismo número arranque limpio.

05 Ejemplo end-to-end

Trazabilidad de un mensaje real desde WhatsApp hasta la cocina.

Mensaje del cliente

"Quiero una Mexa doble y un agua de jamaica, va al centro"

Salida del LLM (validada por Pydantic)

{
  "estado_pedido": "COMPLETO",
  "respuesta_bot": "¡Listo! 1 Mexa Doble + Jamaica al Centro. ¿Efectivo o transfe?",
  "items": [
    {"producto": "Mexa", "cantidad": 1, "es_doble": true, "notas": "Sin notas"},
    {"producto": "Agua de Jamaica", "cantidad": 1, "es_doble": false, "notas": ""}
  ],
  "direccion": "Centro"
}

Agua de Jamaica  $20                     (COGS $0.00)

total_order       $140.00
total_cogs         $73.32
ganancia_bruta     $66.68   (47.6% margen)

orders         { id: "a1b2c3d4e5f6", total: 140.00, status: "PENDING", ... }

                 modifiers: '{"es_doble":true,"notas":"Sin notas"}' }
order_items[1] { name: "Agua de Jamaica", price:  20, quantity: 1, ... }

06 Modelos de datos

Schemas Pydantic + esquema SQL en Supabase.

Pydantic — app/models/schemas.py

IncomingMessage

Entrada del webhook

mensaje_cliente: str
numero_telefono: str

OrdenExtraida

Output del LLM

estado_pedido · respuesta_bot · items[] · direccion · total_order · total_cogs

ItemPedido

Item de orden

producto: str · cantidad: int > 0 · es_doble: bool · notas: str?

WebhookResponse

Respuesta API

status · accion · numero · mensaje_para_enviar · datos_pos · order_id?

SQL — Supabase

CREATE TABLE orders (
  id           VARCHAR(100) PRIMARY KEY,
  customer_name VARCHAR(255),       -- número WhatsApp
  status       VARCHAR(50),          -- 'PENDING' inicial
  total        DECIMAL(10,2),
  cajero_id    VARCHAR(100),         -- 'SUPERADMIN'
  created_at   TIMESTAMP DEFAULT NOW()
);

CREATE TABLE order_items (
  id           SERIAL PRIMARY KEY,
  order_id     VARCHAR(100) REFERENCES orders(id),
  product_id   VARCHAR(100),
  name         VARCHAR(255),
  quantity     INTEGER,
  price        DECIMAL(10,2),
  cogs         DECIMAL(10,2),        -- ⚠ columna nueva
  modifiers    TEXT                  -- JSON encoded
);

CREATE TABLE order_events (
  id           SERIAL PRIMARY KEY,
  order_id     VARCHAR(100) REFERENCES orders(id),
  estado       VARCHAR(50),
  usuario_id   VARCHAR(100),
  created_at   TIMESTAMP DEFAULT NOW()
);
